# Визуализация графа зависимостей NuGet

Программа получает зависимости заданной версии пакета NuGet или читает тестовый
репозиторий, строит граф рекурсивным DFS и выводит его на языке Mermaid.
Одновременно она сохраняет изображение в SVG. По флагу `--ascii-tree` дополнительно
печатается ASCII-дерево. Для получения зависимостей используются NuGet V3 API и
стандартная библиотека Go; готовый менеджер пакетов в алгоритме не применяется.

## Сборка и запуск

Нужен Go 1.22 или новее. Из корня проекта:

```sh
go build -o /tmp/nuget_ku_2_2 ./src
go vet ./...
./run.sh --package A --repository tests/data/graph.txt \
  --test-mode --version 1.0 --max-depth 3 --ascii-tree --output graph.svg
```

Текст Mermaid выводится в терминал, SVG сохраняется в файл `graph.svg` в корне
проекта. Файл можно открыть браузером. Для просмотра Mermaid текст можно
вставить в редактор Mermaid. При ошибке программа пишет сообщение в `stderr`
и завершается с ненулевым кодом.

## Параметры

| Опция | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `--package` | Имя исходного пакета | Обязательна |
| `--repository` | URL NuGet V3 service index или путь к тестовому файлу | Обязательна |
| `--test-mode` | Читать тестовый файл | `false` |
| `--version` | Версия исходного пакета | Обязательна |
| `--output` | Имя создаваемого SVG-файла | `graph.svg` |
| `--ascii-tree` | Показать ASCII-дерево после Mermaid | `false` |
| `--max-depth` | Максимальное число переходов от исходного пакета | `3` |
| `--filter` | Исключить пакеты, имя которых содержит подстроку | Пустая строка |

Имя SVG задаётся без пути и должно оканчиваться на `.svg`. Подстрока фильтра
сравнивается без учёта регистра. При глубине `0` остаётся только исходный
пакет. В тестовом режиме имя пакета состоит из заглавных латинских букв,
а файл содержит строки вида `A: B C`. Строка `D:` задаёт пакет без зависимостей.
Неописанная зависимость считается листом. Повторные определения отклоняются.

Для реального репозитория версия исходного пакета должна существовать точно.
У зависимостей выбирается наименьшая подходящая опубликованная версия.
Поддерживаются минимальные, точные и ограниченные диапазоны версий.
Зависимости из групп разных целевых платформ объединяются. Разрешение
конфликтов версий NuGet не реализовано: разные версии одного пакета могут
остаться отдельными вершинами графа.

## Три примера визуализации

Примеры построены для пакетов `A`, `B`, `C` из `tests/data/graph.txt`.
В файлах `examples/A.txt`, `examples/B.txt`, `examples/C.txt` сохранены
текст Mermaid и ASCII-дерево. Рядом лежат соответствующие SVG-изображения.

| Пакет | Текст | Изображение |
| --- | --- | --- |
| `A` | [A.txt](examples/A.txt) | [A.svg](examples/A.svg) |
| `B` | [B.txt](examples/B.txt) | [B.svg](examples/B.svg) |
| `C` | [C.txt](examples/C.txt) | [C.svg](examples/C.svg) |

Чтобы воспроизвести пример `B`, выполните:

```sh
./run.sh --package B --repository tests/data/graph.txt \
  --test-mode --version 1.0 --max-depth 3 --ascii-tree --output B.svg
```

В тестовом графе есть цикл и общая зависимость. Mermaid и SVG показывают
каждую вершину один раз и сохраняют все связи. В ASCII-дереве повторный
переход отмечается `[повтор]`, а обратный переход по текущей ветке — `[цикл]`.
Поэтому дерево может содержать несколько упоминаний одной вершины.

Для проверки фильтра и ограничения глубины:

```sh
./run.sh --package A --repository tests/data/graph.txt \
  --test-mode --version 1.0 --max-depth 1 --filter D --output filtered.svg
```

В результате остаются `A`, `B`, `C` и две связи от `A`. Для проверки ошибки
можно передать несуществующий тестовый файл или неверное расширение `--output`.

## Сравнение со штатным инструментом NuGet

Для реального пакета использована команда:

```sh
./run.sh --package Serilog.Sinks.Console \
  --repository https://api.nuget.org/v3/index.json \
  --version 5.0.0 --max-depth 2 --ascii-tree --output serilog.svg
```

Программа показывает связь `Serilog.Sinks.Console@5.0.0` с `Serilog@3.1.0`,
а также зависимости `Serilog` от `System.Diagnostics.DiagnosticSource@7.0.2`
и `System.ValueTuple@4.5.0`. Для сравнения выполнен `dotnet restore` проекта
`net8.0` с `PackageReference` на `Serilog.Sinks.Console 5.0.0`. В его
`obj/project.assets.json` оказались только `Serilog.Sinks.Console@5.0.0` и
`Serilog@3.1.0`, со связью между ними. Штатная команда
`dotnet nuget why <проект.csproj> Serilog` показывает путь зависимости
для выбранной платформы. В Mermaid/SVG нашей программы дополнительно есть
два пакета из других групп `.nuspec`, потому что программа объединяет группы,
а NuGet выбирает подходящую для `net8.0`. Также NuGet разрешает конфликты
версий, а программа сохраняет исходные объявления зависимостей.

## Структура и функции

- `src/main.go`: `main` запускает построение и визуализацию;
  `newSource` выбирает источник данных; `exitWithError` сообщает об ошибке.
- `src/config/config.go`: `Parse` читает параметры; функции `validate*`
  проверяют их; `Print` сохраняет вывод первого этапа.
- `src/nuget/`: `NewSource` и `Dependencies` получают данные NuGet;
  функции разбора service index, `.nuspec` и диапазонов версий извлекают
  зависимости; `FetchDirect` и `PrintDirect` сохранены со второго этапа.
- `src/testrepo/testrepo.go`: `Load` читает тестовый граф, `Dependencies`
  возвращает соседей вершины, `Has` проверяет исходный пакет.
- `src/graph/graph.go`: `Build` и рекурсивный `walk` строят граф с учётом
  глубины, фильтра и циклов; `Print` выводит текстовый граф.
- `src/graph/order.go`: `LoadOrder` вычисляет порядок зависимостей для
  четвёртого этапа; `PrintLoadOrder` печатает его.
- `src/visual/`: `PrintMermaid` формирует диаграмму, `WriteSVG` сохраняет
  изображение, `PrintASCII` печатает дерево с пометками циклов и повторов.
- `tests/data/`: тестовые репозитории для ручной проверки.
- `examples/`: текстовые и графические примеры для трёх пакетов.

Документация: [NuGet V3 service index](https://learn.microsoft.com/en-us/nuget/api/service-index),
[PackageBaseAddress](https://learn.microsoft.com/en-us/nuget/api/package-base-address-resource),
[команда dotnet nuget why](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-nuget-why).
