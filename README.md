# Анализатор графа зависимостей NuGet

Программа строит граф зависимостей заданной версии пакета NuGet. Для реального
репозитория она получает адреса из NuGet V3 service index, загружает `.nuspec`
пакетов и списки доступных версий. Граф обходится рекурсивным алгоритмом DFS.
Менеджеры пакетов и сторонние библиотеки для получения зависимостей не
используются; проект написан на Go со стандартной библиотекой.

В текущем этапе программа выводит список пакетов и связей графа. Циклические
связи помечаются `[цикл]`. Порядок загрузки появится на этапе 4, Mermaid,
SVG и ASCII-дерево — на этапе 5.

## Параметры

| Опция | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `--package` | Имя исходного пакета | Обязательна |
| `--repository` | URL service index NuGet V3 или путь к тестовому файлу | Обязательна |
| `--test-mode` | Использовать тестовый файл | `false` |
| `--version` | Версия исходного пакета | Обязательна |
| `--output` | Имя будущего SVG-файла | `graph.svg` |
| `--ascii-tree` | Режим будущего ASCII-дерева | `false` |
| `--max-depth` | Число переходов от исходного пакета, от 0 | `3` |
| `--filter` | Исключать имена, содержащие подстроку | Пустая строка |

Имена в фильтре сравниваются без учёта регистра. Если фильтр исключает
исходный пакет, программа сообщает об ошибке. При глубине `0` в графе есть
только исходный пакет, при глубине `1` — он и его прямые зависимости.

Для реального репозитория версия исходного пакета должна существовать точно.
Версия каждой зависимости выбирается как наименьшая опубликованная стабильная
версия, удовлетворяющая диапазону из `.nuspec`. Поддерживаются минимальные
версии, точные версии в квадратных скобках и диапазоны с открытыми или
закрытыми границами. Если диапазон содержит предварительную версию, она
также участвует в выборе. При отсутствии подходящей версии выводится ошибка.
Зависимости из всех групп целевых платформ объединяются, потому что отдельный
параметр выбора платформы в задании не предусмотрен. Если разные группы
содержат разные ограничения одного пакета, в графе могут появиться несколько
его версий. Программа показывает объявленные зависимости, но не имитирует
правила разрешения конфликтов при `dotnet restore`.

## Тестовый репозиторий

В тестовом режиме `--repository` задаёт путь к текстовому файлу. Каждая
непустая строка имеет вид `A: B C`: слева пакет, справа его прямые зависимости,
разделённые пробелами. Имена состоят только из заглавных латинских букв.
Строка `D:` задаёт пакет без зависимостей. Исходный пакет должен быть указан
слева хотя бы один раз; зависимость без собственной строки считается листом.
Повторные определения и неверные строки отклоняются. Версия из `--version`
используется для всех пакетов тестового графа.

Готовый пример находится в `tests/data/graph.txt`. В нём есть общая
зависимость `D` и цикл `A -> B -> D -> A`.

## Сборка и проверка

Требуется Go 1.22 или новее. Команды выполняются из корня проекта:

```sh
go build -o /tmp/nuget_ku_2_2 ./src
go test ./...
go vet ./...
```

Для проверки полного обхода тестового репозитория:

```sh
./run.sh --package A --repository tests/data/graph.txt \
  --test-mode --version 1.0 --max-depth 3
```

В результате выводятся пять пакетов и шесть связей; связь `D -> A` отмечена
как цикл. Для проверки ограничения глубины и фильтра:

```sh
./run.sh --package A --repository tests/data/graph.txt \
  --test-mode --version 1.0 --max-depth 1 --filter D
```

В этом случае остаются пакеты `A`, `B`, `C` и две связи от `A`. Чтобы
проверить только исходный пакет, установите `--max-depth 0`. Для проверки
ошибки файла можно передать путь к несуществующему файлу.

Пример для реального NuGet:

```sh
./run.sh --package Serilog.Sinks.Console \
  --repository https://api.nuget.org/v3/index.json \
  --version 5.0.0 --max-depth 2
```

Программа выводит прямую связь с `Serilog` и транзитивные связи от него к
`System.Diagnostics.DiagnosticSource` и `System.ValueTuple`. Для сетевой
проверки нужен доступ к указанному репозиторию.

Ошибки параметров, HTTP, JSON, XML и диапазонов версий выводятся в `stderr`.
Программа завершается с ненулевым кодом. Например, версии
`Newtonsoft.Json 5.0.0` в NuGet нет, поэтому запрос заканчивается HTTP 404.

## Структура и функции

- `src/main.go`: `main` разбирает параметры и запускает построение графа;
  `newSource` выбирает источник данных; `exitWithError` выводит ошибку.
- `src/config/config.go`: `Parse` читает и проверяет восемь опций;
  `Print` сохраняет вывод параметров первого этапа.
- `src/nuget/nuget.go`: `FetchDirect` получает прямые зависимости одного
  пакета; функции чтения service index и `.nuspec` разбирают ответы;
  `PrintDirect` сохраняет вывод второго этапа.
- `src/nuget/source.go`: `NewSource` создаёт источник NuGet;
  `Dependencies` получает соседей узла, `listVersions` кэширует списки версий.
- `src/nuget/version.go`: `parseRange` разбирает диапазон, `lowest` выбирает
  опубликованную версию, функции сравнения задают порядок версий NuGet.
- `src/graph/graph.go`: `Build` запускает рекурсивный `walk`, который учитывает
  глубину, фильтр и циклы; `Print` выводит пакеты и связи.
- `src/testrepo/testrepo.go`: `Load` читает тестовый файл, `Dependencies`
  возвращает соседние пакеты, `Has` проверяет наличие исходного пакета.
- `tests/`: проверки конфигурации, NuGet и построения графа на разных случаях.
- `run.sh`: запуск программы из корня проекта.

Описание протокола: [service index](https://learn.microsoft.com/en-us/nuget/api/service-index),
[PackageBaseAddress](https://learn.microsoft.com/en-us/nuget/api/package-base-address-resource),
[формат `.nuspec`](https://learn.microsoft.com/en-us/nuget/reference/nuspec),
[диапазоны версий](https://learn.microsoft.com/en-us/nuget/concepts/package-versioning).
