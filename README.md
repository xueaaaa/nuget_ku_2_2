# Анализатор зависимостей пакетов — вариант №2, этап 1

Минимальный прототип CLI-приложения для будущей визуализации зависимостей
пакетов NuGet. На первом этапе программа читает параметры командной строки,
проверяет их и выводит в формате `ключ = значение`. Получение зависимостей
и построение изображения относятся к следующим этапам задания.

Программа написана на Go и использует только стандартную библиотеку.

## Параметры

| Опция | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `--package` | Имя анализируемого пакета NuGet | Обязательна |
| `--repository` | HTTP(S) URL или путь к тестовому файлу | Обязательна |
| `--test-mode` | Считать `--repository` путём к файлу | `false` |
| `--version` | Версия пакета | Обязательна |
| `--output` | Имя будущего SVG-файла | `graph.svg` |
| `--ascii-tree` | Режим вывода ASCII-дерева | `false` |
| `--max-depth` | Максимальная глубина анализа, от 0 | `3` |
| `--filter` | Подстрока для исключения пакетов | Пустая строка |

В тестовом режиме имя пакета должно состоять из заглавных латинских букв.
Поддерживаются версии вида `1.2`, `1.2.3`, `1.2.3.4` с необязательными
суффиксами предварительной версии и метаданных. Файл `--output` пока не
создаётся.

## Сборка и запуск

Требуется Go 1.22 или новее. Внешние зависимости отсутствуют.

```sh
go build -o /tmp/nuget_ku_2_2 ./src
./run.sh --package Newtonsoft.Json \
  --repository https://api.nuget.org/v3/index.json \
  --version 13.0.3 --output deps.svg \
  --ascii-tree --max-depth 2 --filter System
```

Результат:

```text
package = Newtonsoft.Json
repository = https://api.nuget.org/v3/index.json
test_mode = false
version = 13.0.3
output = deps.svg
ascii_tree = true
max_depth = 2
filter = System
```

Пример тестового режима (файл нужен только для проверки параметра):

```sh
printf 'A: B\n' > /tmp/test-repository.txt
./run.sh --package A --repository /tmp/test-repository.txt \
  --test-mode --version 1.0
```

## Проверка ошибок

Приложение пишет причину ошибки в `stderr` и завершает работу с ненулевым кодом.
Автоматические проверки демонстрируют ошибку для каждой из восьми опций:

```sh
go test ./... -v
```

Примеры неправильных значений (их можно подставить в первую команду запуска):

| Опция | Неправильное значение | Причина |
| --- | --- | --- |
| `--package` | `"bad name"` | Пробел в имени |
| `--repository` | `ftp://example.org` | Не HTTP(S) URL |
| `--test-mode` | `--test-mode=maybe` | Не логическое значение |
| `--version` | `latest` | Не номер версии |
| `--output` | `graph.png` | Ожидается SVG |
| `--ascii-tree` | `--ascii-tree=maybe` | Не логическое значение |
| `--max-depth` | `-1` | Отрицательная глубина |
| `--filter` | `"  "` | Пустая подстрока |

Для `--repository` в тестовом режиме отдельно проверяется существование
и доступность обычного файла. Неизвестные опции и лишние аргументы также
отклоняются.

## Структура и функции

- `src/main.go` — запуск, сообщение об ошибке и код завершения.
- `src/config/config.go` — `Parse` читает параметры; функции проверки
  проверяют имя пакета, версию, URL или файл, имя изображения, глубину и
  фильтр; `Print` выводит восемь пар ключ-значение.
- `tests/config_test.go` — успешный запуск и ошибки параметров.
- `run.sh` — короткая команда запуска из корня проекта.
